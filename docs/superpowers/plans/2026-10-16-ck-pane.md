# C-K Pane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pane docked in the Claude app that shows a C-K session live (SVG map, node picker, node card, operators, K) and turns each operator press into Claude's next turn.

**Architecture:** A Claude Code hooks module (a "mod"), developed in this session's mods folder as `ck-pane` so it hot-reloads, then folded into the `ck-studio` plugin as `hooks/`. Pure functions (fold, layout, SVG, message text) live in their own files and are unit-tested; the hooks module only reads files into `$.state`, draws from it, and submits prompts. The fold is shared with the Node tools through `lib/view.mjs`, from which `lib/view.cjs` is generated.

**Tech Stack:** TypeScript/TSX hooks module against the `claude-code` types (build 2.1.299), `claude plugin validate`, `claude plugin test` (kit `claude-code/testing`), Node 22 for the repo's scripts. No npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-16-ck-pane-design.md`

## Global Constraints

- Mod folder during development: `/Users/dbbz/.claude/dev-mods/2688ef22-3660-4c04-b7b4-e4c2ea426704/ck-pane/`. Its layout mirrors the repo (`hooks/`, `lib/view.mjs`, `types/`, `.claude-plugin/plugin.json`) so Task 8 is a copy plus a rename.
- Plugin name `ck-pane` in every `$.state` reference and in `types/index.d.ts` until Task 8, then `ck-studio`.
- The hooks environment has no DOM, no Node, no `require`, no `import()`, no `eval`/`new Function`. Plugin files are imported with `import` declarations and must be `.ts`, `.tsx`, `.mjs` (etc.); JSON cannot be imported.
- Elements come from `$.ui.resolve(e)`; desktop has `Svg`, terminal does not.
- `Svg` source at most 131,072 characters; drawn with `isInteractive` so `<title>` tooltips work.
- Palette: restrictive `#2a78d6`, expansive `#eb6834` (light); `#3987e5`, `#d95926` (dark). Partition type also carried by an `R`/`E` letter, never by colour alone.
- A render hook never writes state; writes happen in handlers (`update($, atom, fn)`) and in other events.
- Press messages are exact strings (Task 3), ending in ` — pressed in the C-K pane` (spaced em dash).
- "Step n" means n events of the chain folded; its caption is `chain[n-1].summary`.
- Comments in the repo's style: sparse, saying why, not what.
- Commits on branch `ck-pane`; messages in the repo's style (imperative subject, prose body), ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Mod files outside the repo are committed in Task 8.

## Review Focus

1. **Session file caught mid-write.** A read that fails to parse while a good copy of the same file is loaded keeps the good copy on screen; only a file never parsed shows its error. (Test in Task 5.)
2. **Viewed branch or node vanishes.** A branch dropped with `ck drop`, or a node id absent from the branch being viewed, falls back to head and to the latest step's node rather than drawing nothing. (Tests in Task 3.)
3. **`sessions/` emptied or removed while the pane is open.** The pane returns to the empty state with Start a session. (Test in Task 5.)
4. **Text with markup characters.** Attributes and propositions holding `<`, `&` or quotes are escaped in the SVG tooltips. (Test in Task 4.)
5. **A wide or deep tree.** 200 concepts still produce SVG under the size limit. (Test in Task 4.)
